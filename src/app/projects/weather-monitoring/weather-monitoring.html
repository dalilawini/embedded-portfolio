01

Soft-latching power control

The node uses a transistor as a high-side controlled power switch. At startup, the user holds the physical power button long enough to energize the power path and bring up the BMS, regulator and ESP8266.

HOLD BUTTON → POWER APPLIED → MCU BOOTS → GPIO5 LATCH

Once the MCU has booted, GPIO5 continuously drives the transistor control path, allowing the microcontroller to take ownership of the power state. This creates a simple hardware/firmware interface for controlled shutdown.

02

Battery management

The HT4928S stage interfaces the external 5 V charging source with the lithium battery. Its status outputs are connected to GPIO14 and GPIO16, giving the firmware visibility into charging and power-related states.

03

3.3 V power rail

An AMS1117 regulator provides the 3.3 V rail used by the ESP8266 and DHT11 interface, keeping the logic and sensor domain on a common supply.

04 / USER & DIAGNOSTICS

Hardware interaction

A

Power button

A physical button provides the initial power-on event. The user holds the button until the MCU becomes operational and assumes control through GPIO5.

B

Reset button

A dedicated reset input provides a direct hardware recovery mechanism during development and normal operation.

C

Status LED

GPIO4 drives a local status indicator. Firmware can toggle the LED during startup and use different patterns to expose ESP-NOW communication state.

D

UART access

A jumper allows TX/RX access to the ESP8266 for firmware programming, bootloader access and serial diagnostics without changing the deployed wiring.

05 / END-TO-END ARCHITECTURE

From battery to visualization

The resulting architecture combines power autonomy, local hardware control, environmental acquisition and distributed wireless visualization into one embedded system.

⌁
Engineering focus

The design intentionally keeps the sensor node independent from the display. This reduces coupling between acquisition and visualization and creates a reusable distributed architecture: the ESP8266 focuses on sensing and telemetry, while the ESP32 gateway owns the user interface.
